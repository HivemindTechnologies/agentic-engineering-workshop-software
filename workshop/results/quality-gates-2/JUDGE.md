# Judge

You judge the result trees of this lesson. Each tree is its own `## <stamp>` section, with the spec the run wrote under it — judge only that copy. A `# Given to the participant` section, if present, is the starting material the participant saw before the lesson ran, not a result; do not quote from it. The heading list of the spec is the outline.

The participant is told to implement M4. Judge the two claims that decide it, the same way an earlier implement lesson in this journey is judged: a commit, a push, and the question about marking the milestone done need a git history or a second reply, and this run has neither. Those do not decide the verdict.

1. M4 of the spec is `(Status: IMPLEMENTED)`. `(Status: ✅ DONE)` fails this claim. `(Status: PENDING)` fails this claim.
2. That same milestone has a headless `**Implementation Details:**` line. A `### Implementation Details` heading fails this claim.

The verdict is pass only when both claims pass. Each claim quotes one line from the spec and names the tree.

End your answer with one line, alone, either:

```
verdict: pass
```

or:

```
verdict: fail
```
