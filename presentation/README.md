# Workshop presentation

The HIVEMIND agentic-engineering workshop deck: a `reveal-md` presentation.
One spine per deck: the software track has one per half-day, `deck-software-part1.md` and `deck-software-part2.md`, so each part is its own presentation and its own PDF; `deck-infrastructure.md` still holds both infrastructure parts. A spine holds the title slide, the ordered lesson list and the wrap-up; each lesson's slides are one flat `lessons/<id>.md`, shared by every spine that lists it.
`build-deck` splices each spine into `.build/<stem>.md`.
Reorder or skip lessons by editing the `<!-- lessons -->` list in a spine — position is the order.
Exercise material lives in a separate repository per track: software in `HivemindTechnologies/agentic-engineering-workshop-software`, infrastructure in `workshops/infrastructure/`, deleted until it is recreated (`TODO.md`).

## Prerequisites

- Node — the version in `.nvmrc` (22).
- No global npm installs.
  `reveal-md` and `decktape` come from `node_modules/.bin`, which every `.bin/` script puts on `PATH` itself.

## Setup

```sh
cd presentation
npm ci              # installs pinned reveal-md + decktape
```

## Running

| Command | What it does |
| --- | --- |
| `make run deck=software-part1` | assemble the decks and serve `deck-software-part1.md` on `localhost:8000` with live reload (the default deck) |
| `make run deck=software-part2` | the same for any other spine, `deck-<deck>.md` |
| `make build` | assemble every `.build/deck-*.md` |
| `make html deck=<deck>` | self-contained static site in `dist/<deck>/` (fonts + images included) |
| `make pdf deck=<deck>` | `workshop-<deck>.pdf` via headless Chromium, e.g. `workshop-software-part1.pdf` |
| `make stop` | free the serve port |
| `make check` | CI gate: lesson check, every spine builds, static export, no local paths |
| `make new-lesson id=<id> name="<Name>" title="<Full Title>"` | scaffold `lessons/<id>.md` |

`PORT=9001 make run` to use another port.

### PDF note

`reveal-md`'s own `--print` mis-paginates large markdown decks (the markdown plugin splits slides after reveal's print pass runs), so `make pdf` uses a small Puppeteer script (`.bin/_print.mjs`) that waits for the split and lays out the pages itself.
If a dense slide clips, open `http://localhost:8000/deck-software-part1.md?print-pdf` in Chrome and use *Print → Save as PDF* instead.

## Running the workshop

- The menu is the `<!-- lessons ... -->` list in each spine.
  Each line is one lesson id; a leading `#` skips it, `== <title>` opens a part (one half-day), and `-- <title>` opens a block inside it (its own divider slide).
  **Position is the order** — nothing else defines it.
- Each part opens with one slide: the deck title and part name over that part's agenda, generated from the active list.
- Part 1 lists the same lessons in `deck-software-part1.md` and `deck-infrastructure.md`, so a fix to a Part 1 lesson file lands once for both tracks.

## Lessons

One flat `lessons/<id>.md` per lesson, here under `presentation/` (checked by `make check`).
`<id>` is a lowercase word + number (`harness1`, `context1`); the word groups a series, so a lesson that splits becomes `context1` / `context2`.

No frontmatter — the file is plain reveal-md:

- First line is `# 💡 <Name> <n>` (theory) or `# 🏝️ <Name> <n>` (sandbox /
  journey-backed Steckbrief). `<n>` = the id's number; `<Name>` is the slide
  label and the agenda entry.
- A wrapping long-form intro paragraph starting `**<Full Title>.** …`, then `----` sub-slides for the theory.
- Optionally a `---` then `## 🛠️ <Name> <n>`, a long-form scenario paragraph, 3–4 steps, a "done when" checklist only where the steps do not already state the outcome, optionally a material line.
  The exercise fits one slide. A theory-only lesson has none. Sandbox Steckbriefs are generated by `scripts/presentation-bridge` from `workshop/JOURNEY.md` and use 🏝️.
- A drawing slide between lessons is a plain `# <Name>` over an `<img class="drawing">`: no icon, no number, no exercise, not on the agenda. The file holds only the drawing (e.g. `lessons/intent1.md`).

Follow-along material for the exercise is the track's repository, `agentic-engineering-workshop-software` or `workshops/infrastructure/`.
The number in an id is the part the lesson runs in: `harness1` in Part 1, `gates2` in Part 2.

`make new-lesson id=<id> name="<Name>" title="<Full Title>"` scaffolds `lessons/<id>.md` from `lessons/_template.md`.
Then add a line to the list in each spine that should run it.

## Drawings

Hand-drawn figures live in `drawings/*.excalidraw`. Export a drawing from Excalidraw as SVG into `drawings/output/<stem>.svg`, then copy the ones a slide uses into `assets/images/` — only `assets/` is shipped by `make html`. A slide embeds them with `class="drawing"`.

## Pinned versions

- `reveal-md` 6.1.4 (bundles reveal.js 5.1.0)
- `decktape` 3.16.1
- Node ≥ 22 (`.nvmrc`, `package.json` `engines`)

To bump: `npm outdated`, raise the exact pins in `package.json`, `npm install`, regenerate `theme/print-pdf.css` (see its header), then `make check`.
