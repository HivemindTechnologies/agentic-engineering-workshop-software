## Ideas

Most things start small — and Gen AI is named that for a reason: if you let it,
it generates a lot. From a tiny cute sprout, something huge can grow very fast.
To avoid becoming the person eaten by that plant, keep the specification in
good shape so growth stays controlled.

Takeaway: the spec must be **precise yet minimal** — to the point, short enough
to actually read, exact enough to constrain the model. Code will still be
larger than the spec; the goal is that it stays in a controllable field.

Follow-up: that minimal spec is the **control plane** for the behemoth on the
code side — the new natural source of truth. Traditionally it is the other way
around: codebases house only code, and the spec lives elsewhere (Jira,
Confluence, …). Treat the specification more like code and keep it next to the
code so they evolve together. You may still mirror or coexist on wiki/ticket
platforms so a broader audience can talk with you about it — but the living
spec beside the code is what stops the plant from becoming the monster in the
drawing.
