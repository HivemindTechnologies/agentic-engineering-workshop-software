## Ideas

Extended view of the same Idea → Magic → Product frame: after the idea comes
design/sketching and spec, then implementation, testing, release, and once it
is running — operations/maintenance plus customer feedback. All of that is
needed to get a product over the finish line.

AI today lands mostly where code dominates (implementation, testing; sometimes
release and ops via IaC). Expand beyond that: pull ops signals and user
feedback in; go exotic early with high-level design (e.g. Mermaid architecture
before the infra exists) and let that guide the later phases from the start of
a product or feature.

Takeaway: push AI into phases where code is *not* dominant today —
specs stuck unstructured in Confluence/wikis/Jira/GitHub issues, diagrams that
go stale fast. Bridge those so AI can help across the delivery lifecycle.
Every phase here is still a human-in-the-loop process.
