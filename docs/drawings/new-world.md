## Ideas

Biggest takeaway: **documentation flips from burden to accelerant.**

Old world (if you were lucky): requirements → code → maybe document how it was
done. More often: requirements → short description → code, skip docs, then
maybe a few lines later — or bounce code ↔ requirements with documentation
absent. Lack of docs was and still is everywhere.

With automation and AI the incentive flips: explaining the project from scratch
every session gets boring fast, so you write down what matters to get better AI
help. Requirements in → create the documentation together → then craft the
code. Informal specification first; formal specification as code derived from
it — how it should have been, rarely was. Documentation is no longer a burden;
it is the accelerant.
